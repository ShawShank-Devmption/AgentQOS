Project Title and Scope
Title

Agent-Aware Networking: In-Network Classification and Differentiated Transport QoS for AI-Agent Traffic

Scope in one line

A P416/BMv2 switch recognises AI-agent traffic per packet, at line rate, inside the forwarding pipeline, and in the same pipeline pass assigns it a differentiated transport treatment — queue, scheduler share, DSCP/ECN marking, and admission control.

Why it matters

53% of internet traffic is automated. An agent firing 50 parallel MCP tool-calls and a human video call look like 51 identical TLS flows on port 443 — so they queue together, and the human's packets wait behind the machine-paced burst. The network cannot fix what it cannot distinguish.

Project objectives (traceable to NFR targets)

  • Couple that label to a per-class QoS action — DSCP, egress queue, ECN profile, meter — in the same pass (FR-5).

  • Refine decisions in a Ryu controller loop without ever blocking traffic: on any uncertainty the packet stays best-effort — fail-open (NFR-6).

Gap Analysis Identifies What Is Missing

Current state. Agent detection (Cloudflare Web Bot Auth, DataDome, Akamai) lives at the HTTP/CDN edge: it terminates TLS, sees only proxied traffic, reacts on request timescales, and can only allow, block, or rate-limit.

And QoS cannot see agents. DiffServ and port/application marking classify by port and application — agents use real browsers, valid TLS fingerprints, and port 443.

  • Detection exists, but not in the forwarding path.
  • QoS exists, but not keyed to agent identity.
  • Nothing couples the two in one pipeline.

The Proposed System Is the Planned Solution
Definition

The proposed system is the new method designed to solve the problems identified through gap analysis.

Our proposed system

A BMv2 switch running our P4 program parses each packet, updates per-flow timing and size features in registers, evaluates an offline-trained decision tree compiled into range-match tables, and immediately applies the class's DSCP, queue, ECN threshold, and meter. A Ryu controller refines labels out of band via first-packet punts and an entropy-shift reclassification loop.

Course Project Review 19/11
Choose an Algorithm and Explain How It Works
Algorithm identification

Decision tree (depth ≤ 8), trained offline in scikit-learn and mechanically compiled into P4 range-match tables.

Why this algorithm

A tree is the one model a switch can evaluate in a fixed number of table lookups — no loops, no floating point, bounded per-packet cost.

How it works

Ten integer features (timing EWMA, packet sizes, byte ratios, fan-out sketch) are computed in registers with saturating fixed-point arithmetic — shifts only, no division. Each tree path becomes one table entry over feature ranges; the matched entry yields a 2-bit class, which directly selects the QoS action. Classification is re-evaluated at packet checkpoints 6, 16, and 64; before the first checkpoint the flow is UNKNOWN and served best-effort.

Review 1 status: the label-join path is implemented; bit-exact feature arithmetic is explicitly blocked pending four frozen-contract decisions (docs/feature_arithmetic_design_gaps.md).
