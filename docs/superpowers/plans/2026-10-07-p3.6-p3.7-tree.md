# P3.6/P3.7 Train, Compile, Equivalence Gate — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps are TDD:
> failing test → watch fail → implement → pass → commit.

**Goal:** Build the training pipeline, the tree→table compiler (including the generated P4
declarations), the table simulator and the equivalence gate. All of it runs on a seeded synthetic
corpus. Running it on the real corpus waits for Dev C (P3.8) and P3.3.

**Architecture:**
- `ml/train.py` fits the sklearn tree and checks path coverage (§7.14).
- `ml/compile_tree.py` turns the fitted tree into §4.5 JSON plus P4 declarations.
- `common/compiled_tree.classify` simulates the BMv2 range tables. It is shared with the 3.9
  controller, so the gate checks exactly the code the reclassifier will run.
- `ml/verify_equivalence.py` compares sklearn and the simulator: leaf identity and
  (class, punt_reason) must agree on 100% of rows (§7.9).

**Spec:** `docs/design.md` §4.5, §5.3, §7.8, §7.9, §7.14, §8. Roadmap item 4 in
`docs/superpowers/plans/2026-10-07-person2-controller-ml.md`.
**Branch:** `dev-b/p3.6-tree`, stacked on `dev-b/phase-a` (PR #1).

## Global Constraints
Same as the Phase A plan. In addition:

## Decisions (flag at sync)
- **G19 (DESIGN GAP):** generated P4 key paths are `meta.tree_node` (exact) and
  `meta.features.<feature>` (range); actions are `tree_next`/`tree_leaf`, with `NoAction` as the
  default (fail-open: no leaf hit leaves the class UNKNOWN). Dev A must agree on the metadata
  names.
- **float32 thresholds (§7.9):** sklearn compares `float32(x) <= thr`. The compiler emits the left
  range as `[0, k]`, where k is the largest integer with `float32(k) <= thr`. That makes the tables
  agree with sklearn for every integer input, including values above 2^24 where float32 rounds.
- **Disjoint ranges:** each internal node emits exactly 2 entries with disjoint ranges on its
  split feature and wildcards elsewhere, so priority never decides (BMv2's priority direction
  doesn't matter). The simulator treats more than one match as a compiler bug and raises.
- **Low confidence (G15):** a leaf with purity < 0.85 (`max(value)/sum(value)`, class-weighted)
  compiles to `tree_leaf(UNKNOWN, 2)`. The equivalence "expected label" applies the same rule to
  the sklearn leaf.
- **A single-leaf tree** is one level-0 wildcard entry. It also fails the §7.14 path-coverage
  check, so `train` rejects it.
- **CV** is `StratifiedGroupKFold(5)` grouped by `flow_id`. The held-out set is a 20%
  `GroupShuffleSplit` by `flow_id`. Checkpoint rows of one flow never straddle a split.
- **CI gate:** a pytest property test on a deterministic synthetic corpus. The real-corpus check is
  `python -m ml.verify_equivalence …`, run where the corpus lives, with its report committed.

## Review Focus
1. Integer features above 2^24 near a threshold (float32 rounding) — compiled tables must still
   match sklearn.
2. Values exactly at the threshold and at the field maximum.
3. A leaf reached at depth < 8, and a tree that is a single leaf.
4. Low-purity leaves map to UNKNOWN + punt 2 on both sides of the gate.
5. A flow's checkpoint rows leaking across the CV or held-out split.

## Tasks
1. Contracts: `TREE_MAX_DEPTH = 8`, `LOW_CONFIDENCE_PURITY = 0.85`. Add
   `classify(tree, features) -> TreeDecision(traffic_class, punt_reason, leaf_node)` to
   `common/compiled_tree.py`. Test it on a hand-built tree: next→leaf path, early leaf, miss →
   UNKNOWN, ambiguity raises, bad vector length raises.
2. `ml/compile_tree.py`:
   - `compile_tree(model) -> dict`, `leaf_decision(model, node) -> (class, punt_reason)`,
     `left_upper_bound(threshold) -> int`.
   - Tests: the result round-trips through `parse_compiled_tree`; the f32 boundary at 16777217;
     a single leaf; low purity; depth ≤ 8 → tables `tbl_tree_l0..7` only.
3. `emit_p4_declarations() -> str` and `splice_generated_section(p4_text, declarations) -> str`
   (markers `// BEGIN GENERATED: ml/compile_tree.py` / `// END GENERATED`). Tests: 8 tables, the
   key order matches `TREE_KEY_FIELDS`, missing markers raise. Then compile a scratch harness with
   p4c in Docker.
4. `ml/train.py`:
   - `validate_feature_frame`, `split_held_out(frame, seed)`, `check_path_coverage(model)`,
     `train(frame, seed) -> TrainResult`, CLI.
   - Tests: no flow straddles any split; a 0 label is rejected; a path-coverage violation raises;
     the result is deterministic per seed; the report has importances and per-checkpoint P/R.
5. `ml/verify_equivalence.py`:
   - `verify(model, compiled, features) -> EquivalenceReport`, CLI with exit codes.
   - Tests: 100% agreement on the synthetic corpus plus 10k random vectors, including field-max
     and >2^24 values; a tampered entry is detected.

## Found during implementation
- **G20 (DESIGN GAP):** the §7.14 check is a hard failure with no fallback. On synthetic seed 3,
  `tls_ext_count` separates humans perfectly, so a leaf is reached without any timing or burst
  split and `train` refuses the model. That is the documented behaviour, but real data may do the
  same. Options for sync:
  - (a) keep the hard failure and tune features under P4.7;
  - (b) narrow the check to the hazard's wording ("not reachable *only via ratio*");
  - (c) retrain with the TLS/ratio features restricted at the shallow levels.

  Nothing is changed until the team decides.
